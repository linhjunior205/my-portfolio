## Why passwords keep failing

Passwords are reused, guessed, leaked in breaches and typed into convincing phishing pages. Two-factor codes help, but SMS can be intercepted and one-time codes can still be phished in real time.

**Passkeys** take a different approach: there is **no shared secret to steal**. They are built on the WebAuthn standard from the W3C and the FIDO Alliance, and are supported by the major browsers and operating systems.

## How passkeys work

A passkey is a **public/private key pair**:

- The **private key** stays on the user's device (or in their password manager / platform keychain, which can sync it between their devices). It never leaves.
- The **public key** is stored by your server. It is useless to an attacker on its own.

### Registration

1. Your server sends a random **challenge**.
2. The browser asks the authenticator (phone, laptop, security key) to create a key pair for **your domain**. The user confirms with a fingerprint, face or device PIN.
3. The browser returns the **public key** and a credential ID. Your server stores them with the user account.

### Login

1. Your server sends a new random challenge.
2. The authenticator **signs the challenge** with the private key after the user unlocks it.
3. Your server verifies the signature with the stored public key. If valid, the user is logged in.

## Why they resist phishing

The browser binds every passkey to the **domain it was created for**. A passkey for `bank.com` simply will not be offered on `bank-login-secure.com`. Users cannot be tricked into handing it over, because there is nothing for them to type.

## Implementing passkeys

Do not implement the cryptography yourself. Use a well-maintained library such as **SimpleWebAuthn** (TypeScript) or the passkey support in your auth provider.

### Server: generate registration options

```ts
import { generateRegistrationOptions, verifyRegistrationResponse } from "@simplewebauthn/server";

const rpName = "My Portfolio";
const rpID = "example.com";            // your domain
const origin = `https://${rpID}`;

export async function startRegistration(user: { id: string; email: string }) {
  const options = await generateRegistrationOptions({
    rpName,
    rpID,
    userName: user.email,
    attestationType: "none",
    authenticatorSelection: { residentKey: "preferred", userVerification: "preferred" },
  });
  await saveChallenge(user.id, options.challenge); // store to verify later
  return options;
}
```

### Browser: create the passkey

```ts
import { startRegistration } from "@simplewebauthn/browser";

const options = await fetch("/api/passkeys/register/options").then((r) => r.json());
const attestation = await startRegistration({ optionsJSON: options });
await fetch("/api/passkeys/register/verify", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(attestation),
});
```

### Server: verify and store

```ts
const verification = await verifyRegistrationResponse({
  response: body,
  expectedChallenge: await getChallenge(user.id),
  expectedOrigin: origin,
  expectedRPID: rpID,
});

if (verification.verified && verification.registrationInfo) {
  await savePasskey(user.id, verification.registrationInfo); // credential ID, public key, counter
}
```

Login follows the same pattern with `generateAuthenticationOptions` and `verifyAuthenticationResponse`.

## Product and UX tips

- **Offer passkeys alongside existing login at first.** Let users add a passkey after signing in, then prefer it next time.
- **Use autofill UI** (conditional mediation) so passkeys appear in the username field suggestions.
- **Allow multiple passkeys per account** — phone, laptop, hardware key.
- **Plan account recovery carefully.** Recovery is now the weakest link; do not make it a simple SMS code.
- **Let users see and remove** their registered passkeys in account settings.

## Conclusion

Passkeys finally make the secure option also the convenient one. No passwords to remember, nothing to phish, and a simple fingerprint or face check to log in. If your app handles accounts, adding passkey support is one of the highest-impact security upgrades you can make in 2026.

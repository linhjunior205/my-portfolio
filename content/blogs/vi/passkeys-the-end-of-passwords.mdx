## Vì sao mật khẩu cứ thất bại

Mật khẩu bị dùng lại, bị đoán, bị lộ trong các vụ rò rỉ và bị gõ vào những trang phishing trông như thật. Xác thực hai lớp giúp được phần nào, nhưng SMS có thể bị chặn và mã dùng một lần vẫn có thể bị phishing theo thời gian thực.

**Passkey** tiếp cận theo cách khác: **không có bí mật chung nào để đánh cắp**. Chúng được xây trên chuẩn WebAuthn của W3C và FIDO Alliance, và được các trình duyệt và hệ điều hành lớn hỗ trợ.

## Passkey hoạt động thế nào

Một passkey là một **cặp khóa công khai/khóa bí mật**:

- **Khóa bí mật** nằm trên thiết bị của người dùng (hoặc trong trình quản lý mật khẩu / keychain của nền tảng, có thể đồng bộ giữa các thiết bị của họ). Nó không bao giờ rời đi.
- **Khóa công khai** được server của bạn lưu. Một mình nó vô dụng với kẻ tấn công.

### Đăng ký

1. Server gửi một **challenge** ngẫu nhiên.
2. Trình duyệt yêu cầu authenticator (điện thoại, laptop, khóa bảo mật) tạo cặp khóa cho **domain của bạn**. Người dùng xác nhận bằng vân tay, khuôn mặt hoặc mã PIN thiết bị.
3. Trình duyệt trả về **khóa công khai** và một credential ID. Server lưu chúng cùng tài khoản người dùng.

### Đăng nhập

1. Server gửi một challenge ngẫu nhiên mới.
2. Authenticator **ký challenge** bằng khóa bí mật sau khi người dùng mở khóa.
3. Server kiểm tra chữ ký bằng khóa công khai đã lưu. Nếu hợp lệ, người dùng đăng nhập thành công.

## Vì sao chúng chống được phishing

Trình duyệt gắn mỗi passkey với **domain mà nó được tạo ra**. Passkey của `bank.com` đơn giản là sẽ không được đề xuất trên `bank-login-secure.com`. Người dùng không thể bị lừa đưa nó ra, vì chẳng có gì để gõ cả.

## Triển khai passkey

Đừng tự cài đặt phần mật mã. Hãy dùng một thư viện được duy trì tốt như **SimpleWebAuthn** (TypeScript) hoặc phần hỗ trợ passkey của nhà cung cấp xác thực bạn đang dùng.

### Server: tạo tùy chọn đăng ký

```ts
import { generateRegistrationOptions, verifyRegistrationResponse } from "@simplewebauthn/server";

const rpName = "My Portfolio";
const rpID = "example.com";            // your domain
const origin = `https://${rpID}`;

export async function startRegistration(user: { id: string; email: string }) {
  const options = await generateRegistrationOptions({
    rpName,
    rpID,
    userName: user.email,
    attestationType: "none",
    authenticatorSelection: { residentKey: "preferred", userVerification: "preferred" },
  });
  await saveChallenge(user.id, options.challenge); // store to verify later
  return options;
}
```

### Trình duyệt: tạo passkey

```ts
import { startRegistration } from "@simplewebauthn/browser";

const options = await fetch("/api/passkeys/register/options").then((r) => r.json());
const attestation = await startRegistration({ optionsJSON: options });
await fetch("/api/passkeys/register/verify", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(attestation),
});
```

### Server: xác minh và lưu

```ts
const verification = await verifyRegistrationResponse({
  response: body,
  expectedChallenge: await getChallenge(user.id),
  expectedOrigin: origin,
  expectedRPID: rpID,
});

if (verification.verified && verification.registrationInfo) {
  await savePasskey(user.id, verification.registrationInfo); // credential ID, public key, counter
}
```

Đăng nhập theo cùng mẫu với `generateAuthenticationOptions` và `verifyAuthenticationResponse`.

## Mẹo về sản phẩm và UX

- **Lúc đầu hãy cung cấp passkey song song với cách đăng nhập cũ.** Cho người dùng thêm passkey sau khi đăng nhập, rồi ưu tiên nó cho lần sau.
- **Dùng giao diện autofill** (conditional mediation) để passkey xuất hiện trong gợi ý của ô username.
- **Cho phép nhiều passkey trên một tài khoản** — điện thoại, laptop, khóa phần cứng.
- **Lên kế hoạch khôi phục tài khoản cẩn thận.** Khôi phục giờ là mắt xích yếu nhất; đừng biến nó thành một mã SMS đơn giản.
- **Cho người dùng xem và xóa** các passkey đã đăng ký trong phần cài đặt tài khoản.

## Kết luận

Passkey cuối cùng đã biến lựa chọn an toàn thành lựa chọn tiện lợi. Không mật khẩu phải nhớ, không gì để bị phishing, và chỉ một lần quét vân tay hay khuôn mặt để đăng nhập. Nếu ứng dụng của bạn có tài khoản người dùng, thêm passkey là một trong những nâng cấp bảo mật tác động lớn nhất bạn có thể làm năm 2026.
